## Context
修复新建 Qoder 会话时无法选择模型：目前模型目录依赖创建/恢复已有会话，前端又缓存空结果，导致模型选择器不显示。目标是**尚未创建会话也能读取当前 Qoder 账号的真实模型，并将所选模型用于首次发送**。

## 实施方案
1. **独立获取 Qoder 模型目录**
   - 先只读执行 `qodercli --list-models`，确认本机真实输出格式；不猜字段、不硬编码型号、不创建或恢复会话。
   - 新增 `packages/native-runtime/src/agent-runtime/qoder-model-catalog.ts`，复用 `resolveNativeCliCommand()` 的可执行文件、脚本入口和子进程环境，用无 shell 的有界命令执行（超时、输出大小限制）读取并校验目录。
   - 在 `qoder-client.ts` 注入目录加载函数；冷启动从目录获取模型，合并并发请求，失败后允许重试。保留原生会话返回模型的处理和现有 `session/set_model` → `session/prompt` 路径。
2. **修复前端刷新与反馈**
   - 调整 `ChatView.tsx` 的模型加载逻辑：Qoder 创建/切换会话后可重新获取，过期响应不能覆盖当前 Agent 的目录。
   - Qoder 加载中、空目录和失败均给出简短状态；空目录/失败提供重试，不再静默隐藏入口。
   - 未取得有效 Qoder 目录时不清除已保存选择，也不把未经校验的模型随请求发送。保留其他 Agent 的模型来源和现有偏好校验行为。
   - 必要时将请求状态处理抽到小型 renderer 工具中，便于在现有 Node 测试环境验证，避免重构整个 ChatView。
3. **补充回归测试**
   - 目录解析、命令参数/环境、超时/错误、无历史会话也能列模型、并发合并及失败重试。
   - 断言所选模型通过 `session/set_model` 设置，且发生在首次 `session/prompt` 之前。
   - 前端覆盖空结果后创建会话刷新、手动重试、过期请求隔离、加载失败不清偏好；更新直接相关的陈旧源码断言。
