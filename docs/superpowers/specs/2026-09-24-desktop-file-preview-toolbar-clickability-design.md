# AgentRoam Desktop 文件预览工具栏可点击性设计

## 背景

Electron 窗口顶部存在覆盖全宽、52px 高的窗口拖拽区域。文件预览头部也位于该高度内，但其编辑、下载、分享、浏览器预览和关闭按钮没有声明 `-webkit-app-region: no-drag`。Electron 因而把这些按钮所在位置当作窗口拖拽区域，React 已绑定的点击事件无法触发。

文件抽屉左侧头部已经使用 `no-drag`，聊天标题栏操作区也采用相同边界，因此预览工具栏缺失该声明属于桌面组合层的交互遗漏。

## 目标

1. 恢复 Electron 文件预览头部所有按钮的点击能力。
2. 保留文件名和头部空白区域作为窗口拖拽区域。
3. 不改变 WebApp 文件预览行为、文件工作区能力或全局标题栏布局。

## 方案

在 `FilePreview` 的共享头部按钮样式中增加 `WebkitAppRegion: "no-drag"`。所有使用该样式的头部按钮都会从 Electron 拖拽区域中扣除，包括：

- 编辑、取消编辑和保存
- 下载
- 分享
- 进入或退出浏览器预览
- 关闭文件预览

只标记按钮，不把整个预览头部设为 `no-drag`。这样按钮可交互，而文件名和剩余空白仍可拖动窗口。普通浏览器会忽略该 Electron 专用 CSS 属性，因此 WebApp 行为保持不变。

不缩小或重排全局 52px 拖拽层，因为该层同时服务聊天标题栏、侧栏和窗口移动；改变它会扩大回归范围。

## 测试与验收

1. 增加展示层契约测试，断言共享头部按钮样式包含 `WebkitAppRegion: "no-drag"`，同时不要求整个预览头部退出拖拽区域。
2. 运行文件工作区聚焦测试和 Desktop TypeScript 编译。
3. 启动真实 Electron，打开一个 Markdown 文件，验证编辑、浏览器预览和关闭按钮产生对应界面状态变化。
4. 验证下载按钮能完成下载或进入明确的进度/错误状态；分享按钮必须能触发分享流程或显示当前 Electron 平台不支持分享的明确反馈，不能继续表现为无点击响应。

## 非目标

- 新增 Electron 原生分享实现。
- 修改下载、分享、编辑或预览的数据链路。
- 调整文件工作区布局、视觉样式或 WebApp 断点。
- 修改全局窗口拖拽区域。
