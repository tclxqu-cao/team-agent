# AgentRoam 左侧栏参考稿重构设计

## 背景

当前 WebApp 与 Desktop 已支持 Customer Agent、Codex、Claude Code 和 OpenCode 四类 Agent 的独立工作区索引。目录按运行时原生顺序展示，会话按目录懒加载，并按 Agent 隔离缓存、游标、选中状态和滚动位置。

本次只重构左侧栏的展示与局部交互，使其对齐 Ardot 文件“AgentRoam 侧边栏重设计”的最新版本。工作区索引、会话加载、排序、缓存和增量刷新契约保持不变。

## 目标

- 以最新 Ardot 设计稿统一 WebApp 与 Desktop 左侧栏的视觉层级。
- 用四个 Agent 的官方图标替代文字缩写和通用占位图标。
- 提高目录与会话的扫描效率，同时保留所有运行状态和核心操作。
- 保持现有 DDD 边界，不让展示需求渗透到领域层或运行时适配器。

## 非目标

- 不修改 Agent 工作区发现、原生项目映射或 Codex 项目改名同步逻辑。
- 不修改目录原生排序、会话排序开关、会话懒加载或分页协议。
- 不新增消息数、未读数、最后活跃时间等派生数据。
- 不改变会话删除和目录删除的领域语义。
- 不改变聊天主区域、设置页或文件树。

## 视觉结构

左侧栏从上到下分为五个稳定区域：

1. 品牌区：保留 AgentRoam 品牌名称和应用标识。
2. Agent 切换区：横向排列四个图标按钮。
3. 搜索区：使用设计稿中的完整搜索输入框，保留快捷提示。
4. 目录与会话滚动区：目录、会话、加载态和错误态共享同一滚动容器。
5. 底部操作区：固定“新建会话”主按钮，不随目录列表滚动。

左侧栏继续使用当前皮肤变量，不引入只适用于珍珠白皮肤的硬编码颜色。设计稿色值仅用于校准层级和对比度，实际颜色从现有 `--bg-*`、`--text-*`、`--accent`、`--success`、`--danger` 与 `--warning` 变量派生。珍珠白、科幻霓虹和暗夜黑切换后，左侧栏无需重新挂载即可随 CSS 变量即时更新。

### 皮肤与可读性契约

- 标题、正文、次要文字和禁用文字分别使用当前皮肤的 `--text-primary`、`--text-secondary`、`--text-muted` 和禁用态语义，不使用固定黑色或固定白色。
- 官方 Agent 图标使用 `currentColor` 或由当前皮肤变量驱动的单色资产；不得在深色皮肤中保留黑色前景，也不得在浅色皮肤中保留白色前景。
- 会话选中态、搜索框、确认气泡和底部按钮的文字颜色必须与各自背景成对定义，禁止出现黑底黑字、浅底白字或仅依赖透明度碰巧可见的组合。
- 普通文字目标对比度不低于 4.5:1；大号文字、图标、边界和状态提示目标不低于 3:1。无法由静态 token 断言覆盖的组合，在三套皮肤真实页面中读取计算后颜色进行验收。
- hover、focus、active、disabled、loading 和 error 状态都必须在三套皮肤下保持可辨识，不允许状态切换后文字消失。

## Agent 切换区

- 固定顺序为 Customer Agent、Codex、Claude Code、OpenCode。
- 每个按钮使用对应产品的官方图标。AgentRoam 使用仓库现有应用图标；其余图标从各产品官方资产或官方仓库取得，并在代码中记录来源。
- 官方图标只提供可辨识的品牌图形，不引入各品牌原始配色。图标前景、按钮背景、描边、选中态和状态点全部从现有皮肤变量派生，珍珠白、科幻霓虹和暗夜黑保持统一视觉语言。
- 图标按钮使用稳定的正方形尺寸，任何健康状态变化都不能引发布局位移。
- 当前 Agent 使用淡色底、细描边和当前皮肤强调色；未选中项保持透明底。
- 每个按钮保留右上角运行时状态点：可用为成功色，不可用为弱化色。
- 图标按钮保留可访问名称和 tooltip，键盘焦点清晰可见。
- 点击后仍调用现有 Agent 切换流程，只加载该 Agent 的目录并恢复该分区缓存。

## 搜索与目录工具栏

- 搜索入口从单独图标改为设计稿中的完整输入框外观；点击或聚焦后继续打开现有会话搜索体验，不改变搜索数据源。
- “目录”标题与目录数量位于同一行。
- 展开或折叠全部、进行中会话优先、Customer Agent 导入目录等操作继续使用图标按钮。
- 会话排序按钮的语义保持不变：默认关闭时按 `created` 倒序；开启时只把进行中会话稳定置顶，同一分区内仍按 `created` 倒序。

## 目录行

- 沿用当前展开与折叠状态对应的文件夹图标，不替换图标样式。
- 只展示目录名称，不在名称后展示路径。
- 可在右侧展示会话数量和新建按钮；数量不得改变目录的原生顺序。
- 路径仍可用于 `title` 或无障碍描述，以便诊断无效目录，但不作为可见文本。
- 无效目录继续使用警告图标与禁用态。

## 会话行

- 会话采用单行布局：左侧状态圆点、中间单行标题、右侧按需出现的锁图标、子会话展开图标和删除操作。
- 删除完整的第二信息行，不显示 Agent 名称、时间、消息数量或其它元数据。
- 状态圆点保持在标题左侧，并继续表达完成、运行中、待确认和错误四种语义；动态状态保留现有闪烁反馈。
- 当前会话使用设计稿的浅色背景和细描边，普通会话保持扁平。hover 不改变布局尺寸。
- 标题超出可用宽度时单行省略，完整标题通过 tooltip 暴露。
- 外部占用状态使用 Lucide `LockKeyhole` 图标，不再显示“占用”文字徽标。图标提供 tooltip 和 `aria-label="原客户端正在使用，只读"`，避免用户误以为会话可写。
- 子会话保留层级缩进与展开能力，但采用同一单行信息密度。

## 新建与删除交互

- 底部“新建会话”按钮对当前选中目录生效。
- 没有选中目录时，按钮保持禁用并通过 tooltip 说明原因；不隐式选择目录。
- 目录行右侧的新建入口保留，用于直接在目标目录创建会话。
- 桌面 Web 与 Electron 的删除确认采用设计稿中的锚定确认气泡；触屏窄视口使用居中确认框，避免气泡超出视口。
- 删除确认继续调用现有删除应用服务和领域规则。Customer Agent 永久删除、外部 Agent 仅在 AgentRoam 隐藏、运行中会话拒绝删除的语义不变。

## DDD 边界

### 展示层

- `AgentWorkspaceSwitcher` 负责官方图标、选中态、健康状态与可访问标签。
- 左侧栏拆分为边界清晰的展示组件：品牌与 Agent 选择、搜索与工具栏、目录行、会话行、底部主操作和删除确认。
- 展示组件只接收渲染所需的 ViewModel 和命令回调，不直接调用运行时 adapter 或 HTTP API。

### 应用层

- `App.tsx` 继续编排 Agent 切换、目录展开、会话选择、新建、删除和分页加载。
- 若组件拆分需要新 ViewModel，只在 renderer 内建立纯映射函数，不修改领域实体。

### 领域与基础设施层

- `AgentWorkspace`、`Project`、`Session`、Native Runtime Broker、HTTP gateway 和 SQLite 契约不变。
- Agent 官方图标属于静态展示资产，不进入领域模型或接口响应。

## 状态与异常

- 有缓存时先显示缓存内容，并在后台增量对账；刷新期间不清空列表。
- 首次目录加载、目录分页、首次会话加载和会话分页继续使用当前独立 loading 状态。
- 空目录、目录加载失败、部分目录失败使用最新设计稿对应状态；错误提示保留重试入口。
- 不可用 Agent 仍可被选中以查看明确错误，不把按钮直接禁用。

## 响应式与可访问性

- Desktop 与 Web 共用结构和样式；移动抽屉继续使用 `min(82vw, 320px)` 宽度约束。
- 图标按钮、状态点、标题、占用标记和操作按钮使用稳定尺寸，避免动态内容造成跳动。
- 所有图标按钮具备 `aria-label`、tooltip 和键盘焦点样式。
- `prefers-reduced-motion` 下关闭状态点闪烁及非必要过渡。
- 320px、390px 和桌面宽度下不得出现横向溢出、文字重叠或底部按钮遮挡列表。

## 测试与验收

- 组件测试验证四个官方图标、稳定顺序、选中态、健康状态和无障碍名称。
- 展示测试验证目录路径不作为可见文本，会话不存在第二信息行，状态点仍位于标题左侧。
- 行为测试覆盖 Agent 切换、缓存恢复、目录原生顺序、会话排序开关、目录与会话分页、新建和删除确认。
- 运行现有 renderer、workspace cache、sidebar selection 和 session sorting 聚焦测试。
- 完成 Desktop 与 WebApp 构建。
- 使用真实页面在桌面和 390x844 视口验证多目录、空目录、加载失败、部分目录失败、选中会话、运行中、待确认、外部占用与删除确认状态。
- 珍珠白、科幻霓虹和暗夜黑三套皮肤分别验证文字与背景的计算后颜色；不得出现黑底黑字、浅底白字或不可辨识的 hover、disabled 和 selected 状态。
- 发布到 `:3000` 后验证四个健康端点，并确认生产页面加载新侧边栏资源。

## 验收标准

- 四个 Agent 均显示可辨识的官方图标，切换一次点击完成；官方图形不破坏现有皮肤配色。
- 目录图标保持原样，目录行不显示路径。
- 会话行只有状态圆点、标题和必要操作，不存在第二信息行。
- 三套皮肤切换后左侧栏立即换色，所有文字、图标和操作状态保持清晰可读。
- 现有目录顺序、会话排序、缓存、增量刷新、懒加载和删除语义无回归。
- Desktop、桌面 Web 和移动 Web 的左侧栏均与最新设计稿保持一致，并通过无溢出和可操作性检查。
