# 消息区交付物文件链接设计

## 目标

Web App Agent 的助手消息支持展示本地文件交付物链接。用户点击链接后，Web 控制台打开文件抽屉，在文件树中展开并选中目标文件，同时打开现有文件预览。

交付物入口仅来自助手正文中的标准 Markdown 本地文件链接，不自动收集本轮创建或修改的文件，也不重复生成独立交付物列表。

## 链接契约

- 保留现有 HTTP(S) Markdown 链接行为。
- 新增绝对 POSIX 文件路径链接，例如 `[报告](/Users/name/project/outputs/report.pdf)`。
- 接受 Codex 常用的行号后缀，例如 `/path/to/file.ts:120`；文件树与预览使用去掉行号后的文件路径，链接标签仍由消息正文决定。
- 相对路径、`file://`、自定义协议和工作区外路径不在本次范围内。未识别或不安全的目标保持普通文本，不创建可点击控件。

## 展示与交互

- 本地文件链接渲染为紧凑的文件图标加原链接标签，视觉沿用消息区强调色、焦点态和文字换行规则。
- 点击时阻止浏览器导航，通过同源 iframe 消息桥把规范化后的绝对路径发送给外层 Web 控制台。
- 外层控制台只接受当前 Web App iframe、当前 origin 发出的结构化消息；收到后切换到“文件”页签并打开文件抽屉。
- 文件树以当前根目录为优先：目标在当前根目录下时逐级懒加载并展开父目录；目标不在当前根目录下时，将目标父目录设为临时根目录并停止跟随终端目录。
- 目标行增加稳定路径标识，定位完成后选中并滚动到可见区域；现有预览同时打开目标文件。
- 桌面宽度下文件树和预览可同时可见。移动端沿用现有抽屉与预览布局：先完成树定位和选中，再显示文件预览，不新增并排布局。

## 组件边界与数据流

1. `markdown-links` 只负责把文本解析为普通文本、HTTP(S) 链接或本地文件链接，并返回规范化路径与可选行号。
2. `ChatView` 负责本地文件链接的语义化渲染和点击事件，不读取文件系统。
3. Core 的 Web Console 消息契约负责校验消息形状；Web App 仅发送请求，外层页面校验 `origin` 与 `source`。
4. Web Console 页面负责切换抽屉、设置预览路径和把待定位路径传给 `FileTree`。
5. `FileTree` 继续通过现有 `fs:list` 懒加载目录，只新增“展开到目标路径并滚动选中”的能力，不绕过网关访问文件系统。

```text
assistant Markdown
  -> local-file token
  -> click in ChatView iframe
  -> same-origin artifact-open message
  -> Web Console opens Files drawer + preview
  -> FileTree expands ancestors + selects + scrolls target
```

## 错误与安全

- 路径解析不把 URL 解码结果、查询参数或任意协议当成本地路径。
- 外层消息监听器拒绝不同 origin、不同 iframe source、空路径和非绝对路径。
- 文件树仍由现有网关路径策略决定实际可访问范围；目录加载或文件预览失败时显示现有错误状态，不回退到浏览器导航。
- 重复点击同一链接也会重新触发滚动定位，避免目标已选中但不在可视区域。

## 测试与验收

- Markdown 解析测试覆盖 HTTP(S)、绝对路径、带行号路径、危险协议、相对路径和中英文标签。
- 消息渲染测试覆盖文件图标、可访问名称、路径数据以及 HTTP(S) 链接不回归。
- Core/页面桥测试覆盖合法请求、错误 origin、错误 source 和非法路径。
- `FileTree` 测试覆盖当前根目录内逐级展开、根目录外重定位、目标选中及重复定位。
- 运行受影响的 Vitest、Desktop/WebApp/Server 类型检查和 WebApp 构建。
- 按项目规则使用 ego-browser 在桌面与 390px 移动视口验证：链接样式无溢出，点击后文件页签激活，目标行被选中且预览打开。

## 非目标

- 自动推断或汇总工具调用产生的文件。
- 改写 Agent 提示词或引入 `agentroam-file://` 协议。
- 新增文件编辑能力、指定行滚动或桌面端 Finder/系统应用集成。
