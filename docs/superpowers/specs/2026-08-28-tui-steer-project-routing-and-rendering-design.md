# TUI Steer、项目路由与稳定渲染设计

## 背景

Customer Agent TUI 已支持流式思考、工具过程、运行中输入队列、项目候选和模型配置，但真实长会话暴露出四个问题：

1. 运行状态计时器每 250 ms 触发一次 React/Ink 重绘，长 Transcript 会被整块擦除和重画，终端出现持续闪屏。
2. 从 Home 目录输入“进入赔付项目”时，TUI 没有在本地解析项目意图，Agent 会反复调用 `find`，甚至递归扫描整个 Home，造成明显等待。
3. 运行中消息只能等待当前 turn 完成后 FIFO 执行，无法像 Desktop 的“引导”按钮一样插入当前 Agent turn。
4. 消息轨道使用 `YOU / AGENT / TOOL / RESULT` 等长标签，占用较宽的左侧空间，并在长输出中形成重复视觉噪声。

## 目标

- 长会话运行时不再由固定计时器持续触发全帧重绘。
- 流式正文保持及时可见，但通过合并小片段限制重绘频率。
- 普通 Enter 继续把运行中消息加入 FIFO 队列。
- `/steer <序号>` 可以把指定排队消息注入当前 ReAct turn。
- 从 Home 启动时发现 Home 下一级的项目仓库，并用少量项目上下文建立本地搜索文本。
- “进入赔付项目”一类明确项目导航请求在本地直接解析并切换项目，不调用模型或全盘 `find`。
- 使用稳定的等宽符号代替消息角色文本标签，并缩窄左侧轨道。

## 非目标

- 不加入依赖 Nerd Font 的私有区图标。
- 不使用 Emoji 作为消息轨道图标，避免不同终端的宽度和基线差异。
- 不把 TUI 改成全屏 alternate screen，保留终端滚动历史。
- 不读取或绑定个人 Obsidian Wiki manifest 作为运行时必需依赖。
- 不实现任意自然语言文件系统搜索；本次只处理高置信度项目导航意图。
- 不改变 Desktop 的既有队列和 steer 行为。

## 视觉设计

消息、状态和队列统一使用 3 列符号轨道：

| 类型 | 符号 | 颜色语义 |
| --- | --- | --- |
| 用户 | `›` | 绿色 |
| Agent | `◆` | 青色 |
| 工具 | `⚙` | 紫色 |
| 工具结果 | `↳` | 弱化灰色，失败时红色 |
| 错误 | `!` | 红色 |
| 提示 | `i` | 弱化灰色 |
| 运行状态 | `●` | 运行黄色，完成绿色 |
| 排队消息 | `≡` | 黄色 |
| 模型配置 | `◇` | 紫色 |

保留现有左侧竖线和正文结构，只把固定 7 列标签栏缩为 3 列。符号使用普通 Unicode 字符，不要求额外字体。

## 稳定渲染

### 取消固定计时重绘

`ProgressLine` 不再创建 250 ms interval。耗时使用最近一次 Agent 生命周期事件的时间进行渲染，并在 thinking、tool、done、error 等实际状态变化时更新。工具长时间执行期间状态文字保持稳定，避免为了小数级计时刷新整段 Transcript。

### 合并流式正文

App 在消费 Agent events 时建立一个小型事件缓冲器：

- 连续 `text_chunk` 合并到同一字符串。
- 最多约每 80 ms 向 reducer 刷新一次。
- 遇到 `text_done`、`tool_call`、`tool_result`、`done`、`error` 或 `turn_aborted` 时，先同步刷新积压正文，再分发边界事件。
- 组件卸载或 turn 结束时清理 timer，不能丢失最后一段正文。

这样保留流式感知，同时显著减少 Ink 擦除和重写长帧的次数。

## 当前轮消息注入

### Runtime 契约

`TuiRuntime` 新增 `steer(input)`：

1. 校验 Agent 和当前 session 已初始化。
2. 向当前 session 追加 `role=user`、`name=__steer__` 的消息。
3. 不启动第二个 `agent.run()`，避免同一个 Agent 实例并发执行。

Core `AgentLoop` 已在每轮迭代开始时读取 session 新消息，并把 `__steer__` 注入当前 messages，因此 TUI 复用既有协议。

### 命令与队列

- `/steer <序号>` 加入内置命令列表。
- 该命令是运行状态下唯一允许执行的普通内置命令。
- 序号从 1 开始，对应当前可见 FIFO 队列。
- 注入成功后才从队列移除消息，并在 Transcript 中显示该用户消息。
- 队列区域显示 `/steer 1 插入本轮` 提示。
- 序号缺失、越界、当前未运行或队列为空时显示明确错误，不改变队列。
- `ask_user` 回答仍拥有最高优先级，不经过 `/steer`。

注入发生在工具执行期间时，Core 会在下一次 ReAct 迭代读取。若当前 turn 已结束，则命令不会伪装成已插入；此时保持 FIFO 行为。

## 本地项目导航

### 项目发现

项目发现保持低成本和通用性：

- 普通项目目录启动时继续扫描当前项目的兄弟目录。
- 从用户 Home 根启动时，改为扫描 Home 的一级子目录，而不是 `/Users` 下的其他用户目录。
- 仅把包含项目 marker（如 `.git`、`package.json`、`pom.xml`）的目录加入项目候选。
- 对每个候选最多读取固定数量的已知轻量上下文文件前缀，例如 `README.md`、`docs/project-context.md`、`AGENTS.md`、`CLAUDE.md`。
- 读取失败直接跳过；每个文件有大小上限，不递归扫描文档。
- 候选搜索文本包含目录名、绝对路径和上下文文件前缀，因此 `refund` 项目可被中文“赔付”命中。

### 导航意图

本地解析器只处理含明确导航动词和项目/目录/仓库目标的输入，例如：

- `进入赔付项目`
- `切换到 refund 仓库`
- `打开 customer-agent 项目`

解析规则：

1. 从输入移除导航模板词，得到项目查询词。
2. 对候选的 label、path 和本地搜索文本做包含匹配与优先级排序。
3. 唯一高置信度命中时直接调用 `runtime.switchProject()`，新建 session，并显示切换结果。
4. 多个同分命中时打开已过滤的项目候选列表，由用户确认。
5. 没有命中时才把原消息交给 Agent，不伪造目录。

项目切换完成后不再把“进入项目”原句发送给 Agent，避免 Agent 重复搜索。

## 错误处理

- 项目 metadata 文件不可读不会阻断其他候选。
- Home 项目扫描有明确深度和 marker 边界，不允许退化为递归全盘搜索。
- `steer()` 持久化失败时保留原队列消息并显示错误。
- 项目切换构建 Agent 失败时保留原工作目录和 Agent。
- 流式缓冲器在边界事件前强制 flush，确保事件顺序和最终文本完整。

## 测试与验收

### 单元与组件测试

- 角色符号、3 列轨道和队列 steer 提示渲染。
- ProgressLine 不再通过 interval 产生空闲重绘。
- 连续正文 chunk 合并、边界事件前 flush、timer 清理和顺序保持。
- `/steer 1` 成功、越界、非运行状态和持久化失败。
- steer 消息以 `__steer__` 写入当前 session。
- Home 一级项目发现不会扫描更深的非项目目录。
- 项目上下文中文词可把“进入赔付项目”唯一解析到 `refund`。
- 多匹配打开候选、无匹配回退 Agent。

### 真实 PTY

- 制造长 Transcript 和 3 秒工具等待，确认等待期间不再每 250 ms 闪屏。
- 模拟高频 text chunks，确认正文连续显示且没有丢字。
- 当前 turn 工具执行时发送两条排队消息，执行 `/steer 1`，确认该消息进入下一次 ReAct iteration，另一条仍在队列。
- 从 `/Users/caoqu` 启动，输入“进入赔付项目”，确认直接切换到 `/Users/caoqu/refund`，不出现 Home 全盘 `find`。
- 确认本地终端、60 列和 80 列下符号轨道不重叠、不乱码。
