# Sherpa ONNX Chinese ASR POC Design

## Goal

Validate whether a local sherpa-onnx streaming Chinese model provides a practical replacement for the current `SFSpeechRecognizer` transcription path, without changing the production wake, dictation, or TTS barge-in flow.

## Scope

- Add an isolated desktop ASR POC that accepts either a WAV/AIFF file or the macOS microphone.
- Convert audio to mono 16 kHz float PCM with the installed FFmpeg.
- Stream PCM into sherpa-onnx and print changing partial text plus endpoint/final text.
- Measure native module load time, model load time, first partial latency, final latency, process RSS, and CPU time.
- Validate deterministic Chinese phrases generated by `say`, then validate the physical microphone.
- Keep model files, generated audio, and POC dependencies out of Git.

## Non-Goals

- Do not replace `packages/desktop/native/wakelistener.swift`.
- Do not alter wake-word matching, input dictation, conversation routing, or TTS interruption.
- Do not ship a model or add sherpa to the desktop production dependency graph.
- Do not claim the POC removes model startup cost; startup and model load are measured explicitly.

## Options Considered

### Electron main-process addon

Lowest eventual process count, but it couples the experiment to Electron loading, packaging, native library paths, and signing. It is premature before recognition quality is known.

### Isolated Node/FFmpeg POC

The selected approach. It uses the official Node-API addon and an existing FFmpeg installation, so recognition quality and latency can be measured without touching the product path. It also exposes installation and dynamic-library issues before Electron packaging is involved.

### Swift capture plus local ASR sidecar

Likely the safest production migration if Electron addon loading or microphone TCC attribution is unreliable. The existing Swift helper already has calibrated VAD, voice processing, and TTS barge-in behavior. This option remains the fallback after the POC.

## Dependencies and Version Constraints

- macOS arm64, Node.js 16 or newer, FFmpeg with AVFoundation input.
- Pin `sherpa-onnx-node` to `1.13.4`. Version `1.13.5` declares a macOS arm64 package that was not published when checked on 2026-08-11.
- Start with `sherpa-onnx-streaming-zipformer-zh-int8-2025-06-30` (about 126 MiB). The available streaming Paraformer bilingual archive is about 999 MiB, so download it only if the smaller current Chinese model needs a quality comparison.
- Store downloaded models under `packages/desktop/.agent-data/asr-models/`.

## POC Interface

The command accepts `--model-dir`, exactly one of `--input <audio-file>` or `--microphone [device-index]`, and optional `--json`. Human output redraws partial text and prints final lines. JSON output emits one record per lifecycle, partial, endpoint, metric, or error event for repeatable evaluation.

FFmpeg emits `f32le`, 16 kHz, mono PCM on stdout. The POC maintains incomplete-byte carryover, converts complete 32-bit little-endian samples to `Float32Array`, feeds the online recognizer, decodes while ready, and resets on endpoint.

## Error Handling

- Validate required model files before loading the native addon.
- Report missing addon, missing FFmpeg, bad model directory, bad input file, and microphone subprocess failure with actionable messages.
- Terminate FFmpeg on SIGINT and flush the recognizer with `inputFinished()` before exit.
- Never download a model implicitly during recognition; model installation is an explicit command.

## Acceptance Criteria

- Unit tests prove argument validation, PCM carryover handling, and metric aggregation.
- The pinned addon loads under local Node and reports its measured load time.
- A fixed `say -v Tingting` phrase set produces transcripts and a metrics report.
- Live microphone input produces at least one partial and one final transcript, or the exact macOS permission/device blocker is recorded.
- The report compares startup, latency, punctuation, CPU/RSS, Chinese output, and integration friction against the existing Swift path.
