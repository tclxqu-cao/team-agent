# 交付物预览原生文件分享设计

## 目标

在 Web 端交付物预览右上角增加文件分享按钮。用户点击后调起当前设备的系统分享面板，并将正在预览的文件本身交给微信、企业微信、QQ 等已注册为系统分享目标的应用。

## 交互

- 非编辑状态下，在“下载”按钮右侧、“关闭”按钮左侧显示 Lucide `Share2` 图标按钮。
- 分享过程中禁用按钮并显示加载状态，避免重复读取和重复打开分享面板。
- 文本文件进入编辑状态后隐藏分享按钮，防止用户误以为未保存草稿会被分享。
- 用户主动关闭系统分享面板时保持静默，不显示失败信息，也不触发下载。
- 分享完成后短暂显示完成状态。

## 实现

复用 `FilePreview` 已有的分块读取能力，从网关读取完整文件并创建带原文件名和合理 MIME 类型的浏览器 `File`。先通过 `navigator.canShare({ files })` 判断当前浏览器是否支持文件分享，再调用 `navigator.share({ files, title })`。

文件读取仍受现有 256 MiB 客户端下载上限约束。浏览器不提供文件分享能力或 `canShare` 拒绝该文件时，复用已读取的文件数据触发下载，并提示“当前浏览器不支持直接分享文件，已改为下载”。除用户取消外的读取或分享错误显示在预览内容区，不静默吞掉。

分享目标由操作系统和已安装应用决定，Web 页面不维护微信、企业微信或 QQ 的私有协议，也不上传文件或生成公网链接。

## 代码边界

- 主要修改 `packages/server/app/web/FilePreview.tsx`。
- 将文件读取、原生分享判断和取消识别拆成可测试的纯接口边界，不新增服务端上传接口。
- 保持现有头部按钮尺寸、颜色、提示文本和键盘可访问性。

## 验证

- 单元测试覆盖：支持文件分享、用户取消、浏览器不支持后下载、文件读取失败。
- 运行 `FilePreview` 聚焦测试与 Server TypeScript 检查。
- 在桌面和 390 x 844 移动视口检查按钮不挤压文件名、无重叠，分享状态不会改变头部几何。
