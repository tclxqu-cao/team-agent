# 排队消息操作设计

## 目标

排队消息区域移除顶部“排队消息（N）”标题行。每条排队消息在尾部提供引导、复制、编辑、删除四个纯图标操作，并通过 `title` 与 `aria-label` 说明用途。

## 交互

- 引导：沿用现有能力，将该条消息注入当前运行中的 Agent；运行时不支持引导时不显示。
- 复制：将消息正文复制到系统剪贴板，不改变队列状态。
- 编辑：当前行切换为单行输入框；回车或勾选保存，`Esc` 取消。空白内容不能保存。
- 删除：立即从当前会话队列移除该条消息，不影响其他排队消息与正在运行的消息。
- 编辑态保留复制和删除；原编辑图标替换为勾选图标，取消使用输入框的 `Esc`，避免增加第五个常驻操作。

## 状态与数据流

`ChatView` 保存当前编辑消息 ID 和草稿文本。保存通过现有 `updateMessage` 更新 `content`，复制复用 `copyTextToClipboard`。删除通过 `setMessages` 对当前会话消息列表做 ID 过滤，并显式传递当前会话 ID，保证 `messages` 与 `messagesBySession` 一致。

队列消费仍按现有 `messages.find(message => message.isQueued)` 顺序执行。编辑不生成新消息，因此不会改变排队次序、目标 Agent 或附件信息。

## 错误与边界

- 操作前再次确认目标消息仍为 `isQueued`，避免与队列自动消费竞争。
- 当前正在编辑的消息被引导、删除或自动消费后，清空编辑状态。
- 剪贴板失败沿用页面现有错误提示入口。
- 只修改排队栏，不改变历史消息气泡和底部输入框行为。

## 验证

- 源码回归覆盖标题行移除、Lucide 图标、复制/编辑/删除处理器和编辑键盘行为。
- Desktop 与 WebApp 类型检查、相关 Vitest、WebApp 生产构建通过。
- 在 `:3000/app/` 真实页面构造多条队列，验证编辑保持顺序、复制内容正确、删除只影响目标项，并检查桌面与移动宽度不溢出。
